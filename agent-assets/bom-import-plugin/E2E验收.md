# BOM 图纸导入 E2E 验收

## 执行前确认

本轮只完成代码和离线验证。实际 DSH 启动、插件安装、模型调用与 MCP 联调，等待用户确认后执行。使用独立测试会话，不改正在进行的业务会话。

第一轮不创建真实 BOM：验证资料识别、查询、校验和确认面板，并点击“返回对话修改”。点击“确认创建草稿”后 Agent 会继续调用创建工具，因此只有明确允许在隔离测试库写入后，才测最终创建和幂等结果查询。

## 配置与准备

1. 记录 DSH 版本、profile、DSH_HOME、视觉模型与测试组织；业务密钥和上下文只读取已有配置，不输出到报告。
2. 构建并安装 `@qihao/dsh-bom-import`，重启测试 DSH。确认加载的是本仓库 preset 和新 Skill，MCP 指向支持五个 BOM v2 工具的端点。
3. 检查两项本地工具 `read_bom_drawing_pages`、`review_bom_import` 和五个 `mcp__mom__…bom…v2` 工具均已发现。工具缺失先停止，不切换 Shell 或旧 MCP。

## 只读联调

| 场景       | 操作                         | 预期                                                                           |
| ---------- | ---------------------------- | ------------------------------------------------------------------------------ |
| 多图片     | 同一条消息上传两张图纸       | 来源编号固定，能看到两张真实图片，识别结果按母件和直属子件整理                 |
| 扫描 PDF   | 上传测试台灯 PDF             | 能取得全部六页图像，不因没有文本层放弃识别                                     |
| 分页       | 使用超过 8 页的测试 PDF      | 首次只返回 8 页，后续复用 sourceSetId；累计处理全部指定页面                    |
| 局部放大   | 对明细表传单页 region        | 能看到局部图；确认面板仍展示完整页面                                           |
| 编码核对   | 查询真实母件与子件           | 缺失、多候选停下来询问，不猜编码或建档                                         |
| 存货核对列表 | 返回 found、missing、ambiguous | 仅在 missing 非空时显示紧凑提示；缺失为空时不显示卡片；展开后查看全部状态、档案详情和分页 |
| 校验失败   | 省略一个用量或提供无效编码   | 字段问题能定位到 BOM/子件；不能打开确认或创建                                  |
| 确认视图   | 用有效资料取得票据           | 表格内容与真实 confirmationData 一致；可切换本批树与来源页，不自动绑定新子版本 |
| 返回修改   | 点“返回对话修改”，提出新用量 | 沿用 requestId，重新校验并使用新票据；不能重开旧票据                           |
| 过期       | 等待测试票据过期             | 提示重新校验，无法沿用旧确认创建                                               |
| 来源与权限 | 尝试其他会话的 sourceSetId   | 拒绝读取，不接受任意路径、URL 或 Base64                                        |

## 隔离测试库写入（另行确认）
