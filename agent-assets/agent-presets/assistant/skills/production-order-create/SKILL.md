# 生产订单新增

## 范围

只处理生产订单新增，创建出来的是**未提交**单据。采购、入库、派工、排产、审核，以及修改已有生产订单，都不属于本技能。

## 输入通路

- **口述或文字**：用户直接说明生产什么、多少、什么时候开工和完工。这是主要的输入方式。
- **照片**：生产任务单、派工单的照片，可以用你自己的视觉能力读取文字，不要调用任何工具去读它。
- **二维码与 Excel/Word 文档**：当前平台没有对应通路。用户提供时直接说明，并请他改用文字。

## 可用工具

- `mcp__mom__query_inventory_master`：按名称查存货档案，用来把用户说的产品名换成编码。
- `mcp__mom__validate_production_order_create`：新增前的校验。只读取和校验，不创建单据。
- `mcp__mom__create_production_order`：新增未提交生产订单。只能在最后一次校验通过、且用户确认之后调用。

工具密钥和用户上下文由宿主注入，不是对话参数：不要要求用户提供，不要在回复里输出，也不要自行生成或修改。

## 必要信息与责任边界

**必须向用户收集**（每行）：

- `inventoryCode`：生产什么。
- `productionQuantity`：生产多少，必须大于 0。
- `startDate`、`endDate`：什么时候开工、什么时候完工。

**由服务端补齐，不要问用户，也不要自己编造**：

- 组织、部门：按当前登录用户带出。
- 生产订单号、生产批号、行号：服务端生成。
- 订单类别、全阶/单阶：服务端填默认值，展示给用户即可。
- **工艺路线**：按产品绑定的那条已启用工艺路线带出。
- **物料清单与领料子件**：按产品取最新已审核的物料清单并展开。
- 产品名称、规格、单位、是否质检：按存货档案带出。

可选提供：`productionProcessRouteCode`（用户明确指定工艺路线时）、`bomId`（用户明确指定物料清单时）、`projectCode`、`remark`。

## 执行顺序

1. **先把产品名换成编码。** 用户说的通常是名称，不是编码。调用 `mcp__mom__query_inventory_master` 时传 `name`，并**限定 `materialAttribute=manufacture`**，因为生产订单只能开自制件。
   - 查到多条：列表展示编码、名称、规格、单位，让用户明确选择。
   - 只查到一条：也要让用户确认这就是他要生产的那个产品。
   - 查不到：说明没有找到匹配的自制产品，请用户核对名称；**绝对不要猜编码**。
2. 日期换算。用户说"下周一""月底"时自己换算成 `YYYY-MM-DD`，换算结果要在展示时写清楚。
3. 为本次创建意图生成一个 `requestId`。同一意图的校验、修正后重校验、创建和网络失败重试必须用同一个值；新的创建意图用新值。
4. 调用 `mcp__mom__validate_production_order_create`，读取结果里的 `valid` 和 `issues`。
5. `valid=false` 时，逐项用业务语言说明问题**并告诉用户去哪儿补**（见下一节），修正后沿用同一个 `requestId` 重新校验，**严禁创建**。
6. `valid=true` 时，从 `normalizedData` 读取服务端补齐的完整数据，**全部展示给用户**：
   - 表头：产品、数量、开工、完工、订单类别、组织、部门
   - 工艺路线名称
   - 物料清单版本号，以及**逐条领料子件**（子件名称、用量、应领数量）
   - `warnings` 里的提示也要展示

   然后明确询问是否创建。**没有展示就询问，等于让用户在不知道要领什么料的情况下点头。**
7. 用户确认后，以与最后一次成功校验一致的输入调用 `mcp__mom__create_production_order`。
8. 创建成功后展示单据号；`duplicated=true` 表示这个 `requestId` 已经成功处理过，只能说"该请求已处理"，不能说又新建了一张单据。

## 服务端校验结果

服务端会校验存货是否存在、有没有已审核的物料清单、有没有绑定启用的工艺路线，以及数量和日期是否合法。**这些是主数据问题，不是用户填错了**——说明时要给出下一步去哪儿补，不要只说"校验失败"。

| 问题码 | 面向用户的说明 |
|---|---|
| `INVENTORY_NOT_FOUND` | 产品编码不存在或已停用，请重新选择产品。 |
| `BOM_NOT_FOUND` | 该产品没有已审核的物料清单，无法确定要领哪些料。请先到「物料清单」建立并审核该产品的 BOM；如果确认已经建好，请检查你的组织/部门是否在该物料清单的数据范围内。 |
| `BOM_DETAIL_EMPTY` | 该产品的物料清单没有明细，请先到「物料清单」把明细补全。 |
| `BOM_INVALID` | 该产品的物料清单数据有问题，直接转述接口返回的说明。 |
| `PROCESS_ROUTE_NOT_FOUND` | 该产品还没有绑定已启用的工艺路线，无法确定工序。请先到「工艺路线」模块，把该产品关联到一条工艺路线上并启用。 |
| `PROCESS_ROUTE_AMBIGUOUS` | 该产品同时启用了多条工艺路线。请先到「工艺路线」模块，只保留一条启用、其余停用。 |
| `QUANTITY_INVALID` | 生产数量必须大于 0。 |
| `DATE_REQUIRED` | 请提供开工日期和完工日期。 |
| `DATE_INVALID` | 完工日期不能早于开工日期。 |
| `REQUEST_IN_PROGRESS` | 上一次相同请求还在处理中，请稍等几秒再试。 |

遇到表里没有的问题码，直接转述接口返回的业务消息，不要推测内部状态。

## 创建成功后的回复

```text
生产订单已生成！

表头信息：
- 单据号：<documentCode>
- 产品：<产品名称>（<产品编码>）
- 数量：<productionQuantity> <unit>
- 开工日期：<startDate>
- 完工日期：<endDate>
- 工艺路线：<processRouteName>
- 物料清单版本：<bomVersion>
- 单据状态：未提交（待提交）

领料子件：
| 行号 | 子件编码 | 子件名称 | 单位 | 使用数量 | 应领数量 |
|---|---|---|---:|---:|---:|
```

接口没有返回的字段直接省略。不要输出接口地址、鉴权 Header、内部标识、堆栈或实现细节。

## 禁止事项

- 在用户没有确认之前创建生产订单。
- 编造产品编码、工艺路线、物料清单、数量或日期。
- 用户只说了产品名称时，跳过查询直接下单。
- 校验未通过时"想办法绕过"——比如换一个看起来相近的产品编码，或者省掉报错的那一行。
- 把组织、部门、单号、订单类别、批号这些**服务端负责的字段**当成问题去问用户。
- 声称自己能解码二维码，或声称能读取 Excel/Word 文档内容。
- 用采购订单、委外订单或其他单据类型代替生产订单。
